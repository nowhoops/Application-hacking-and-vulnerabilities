## Root Cause
The function is likely:

```  
void print_scrambled(char *message) {  
    register int i = 3;  
    do {  
        printf("%c", (*message) + i);  
    } while (*++message);  
    printf("\n");  
}  
```
**I checked it it was correct**

The crash occurs because:

- `bad_message = NULL`  
- it breaks the function and causes a **segmentation fault**.

---
There were no clear explenation on what a fixed code should do. I found two fixes that don't break the code. 

### Fix Option 1 — Make the NULL a String

```  
#include <stdio.h>

void print_scrambled(char *message)
{
  register int i = 3;
  do {
    printf("%c", (*message)+i);
  } while (*++message);
  printf("\n");
}

int main()
{
  char * bad_message = "NULL";
  char * good_message = "Hello, world.";

  print_scrambled(good_message);
  print_scrambled(bad_message);
}
```

Output:

```
Khoor/#zruog1
QXOO
```

---

### Fix Option 2 —  IF NULL then message

```  
#include <stdio.h>

void print_scrambled(char *message)
{
    if (message == NULL) {
        printf("ERROR: NULL message\n");
        return;
    }

    int i = 3;
    do {
        printf("%c", (*message) + i);
    } while (*++message);
    printf("\n");
}

int main()
{
  char * bad_message = NULL;
  char * good_message = "Hello, world.";

  print_scrambled(good_message);
  print_scrambled(bad_message);
}
```

Output:

```
Khoor/#zruog1
ERROR: NULL message
```

---

## SUMMARY
- The crash occurs because `print_scrambled()` does not work with a NULL pointer.  
- Two valid fixes:  
  - Replace NULL with a real string  
  - Add a NULL check inside the function

# 🟢 Part 1 — Cracking `passtr`

## Running in GDB
```  
gdb passtr  
```

I stepped through the program until it asked for a password.  
I entered something random, and then saw the comparison:

```
if (0 == strcmp(password, "sala-hakkeri-321"))
```

So the password is:

```
sala-hakkeri-321
```

Running the program normally and entering the correct password prints the **flag**.

(Flag shown in screenshot in original notes.)

# 🔵 Part 2 — Cracking `passtr20`

This binary is **stripped**, so no function names, no source code, and no symbols.  
Much harder.

Running it normally:

- It immediately prints **“Sorry, no bonus.”**
- Even with correct password attempts, it fails instantly.

So the password is **not** visible in memory during normal execution.

---

# 🔍 Step 1 — Inspecting Functions

I noticed a function at address labeled by GDB as:

```
mAsdf3a
```

This is likely the password‑checking function.

I set a breakpoint:

```  
break mAsdf3a  
run  
```

Then I inspected the disassembly:

(Screenshot in original notes.)

I saw a suspicious string:

```
anLTj4u8
```

I tried it as a password — **not correct**.

---

# 🔍 Step 2 — Hunting Through `strcmp`

I set a breakpoint on `strcmp`:

```  
break main  
run  
break strcmp  
continue  
```

Then I entered a test password like:

```
AAA
```

I inspected the arguments:

```  
x/s $rdi  
x/s $rsi  
```

But the values were things like:

- `"strlen"`
- `"GLIBC_2.2.5"`

So this was not the password comparison.

---

# 🔍 Step 3 — Inspecting `main` Logic

I disassembled `main`:

```  
disassemble main  
```

(Screenshot in original notes.)

I identified the key instruction:

```
dec %eax
```

This is part of a conditional jump:

- If `%eax == 0`, it jumps to the **success** branch  
- Otherwise, it prints **“Sorry, no bonus.”**

So instead of finding the password, I can **force the program to think the password is correct**.

---

# 🧠 Step 4 — Forcing Success in GDB

I set a breakpoint at the instruction:

```
0x555555555105
```

```  
break *0x555555555105  
run  
```

At the breakpoint, I tried:

### Attempt 1 — Force success with `eax = 0`
```  
set $eax = 0  
continue  
```

This still went to **“Sorry, no bonus.”**

### Attempt 2 — Try `eax = 1`
```  
set $eax = 1  
continue  
```

This time it **jumped to the success branch** and printed the **flag**.

(Screenshot in original notes.)

---

### Final Result

- **`passtr`**: Password found directly in GDB → `sala-hakkeri-321`  
- **`passtr20`**: Password not recovered, but **flag obtained** by manipulating CPU registers in GDB  
- The key trick:  
  - Break at the conditional jump  
  - Modify `%eax` to force the program to take the “correct password” path  

---

### Summary

| Binary      | Method Used | Password Found | Flag Obtained |
|-------------|-------------|----------------|----------------|
| passtr      | Source + GDB stepping | Yes | Yes |
| passtr20    | Reverse engineering + register manipulation | No | Yes |

This demonstrates two classic approaches:

- **Static/dynamic analysis** for binaries with symbols  
- **Runtime manipulation** for stripped binaries  

Both are valid techniques in application hacking labs.
